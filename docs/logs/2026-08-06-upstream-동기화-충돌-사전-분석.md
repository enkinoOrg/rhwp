## 의미적 충돌

### 임베드 대화상자 정책

upstream SDK는 `loadFile` options에 `suppressDialogs`가 없으면 `true`를 전달한다.
upstream Studio는 #2527 정책으로 HWPX 검증 모달을 전역적으로 표시하지 않고
‘그대로 보기’로 연다.

Enkino 운영 계약은 다르다.

- 정확한 boolean `suppressDialogs: true`일 때만 대화상자를 생략한다.
- 옵션 누락·`false`·문자열 `"true"`는 기존 대화형 동작을 유지한다.
- 자동 보정으로 해결된 `LinesegArrayEmpty`는 보고에서 제거하되, 실제로
  남은 경고는 표시한다.

따라서 upstream의 `npm/editor/index.js`와 `rhwp-studio/src/main.ts`를 그대로 채택하면
기존 Enkino 연동 문서와 운영 동작이 바뀐다. 이는 자동 해결 대상이 아니라
사업 정책 선택이다.

### SDK 구조

upstream은 전송·origin/source 검증·timeout·destroy를 `npm/editor/transport.js`로
분리했고 v1 MessageChannel handshake와 legacy fallback을 추가했다. Enkino의 기존
`index.js` 구현을 통채로 선택하면 upstream 보안·프로토콜 개선을 잃는다.
upstream 구조를 유지하고 Enkino의 호스트 URL·정책·회귀 테스트만 이식해야
한다.

### lineseg 경고 정합

upstream도 검증 후 로드 자동 reflow 순서를 유지하여 선검증 보고가 남는
문제가 있다. 다만 HML, HWP5-origin marker, cell-empty 보정 등 새 조건이 추가돼
있으므로 Enkino 파일을 선택하면 안 된다. upstream 구조 위에 HWPX 후검증
최소 패치와 회귀 테스트를 다시 적용해야 한다.

### 배포 정책

`.github/workflows/deploy-pages.yml`은 upstream이 유지·수정했지만 Enkino는 Cloudflare
Workers만 운영하므로 삭제 상태를 유지하는 편이 기존 정책과 일치한다.

## 위험도와 권고

동기화는 **가능하지만 단순 merge나 일괄 `ours/theirs` 선택으로는 안 된다**.
추천 방식은 새 upstream HEAD에서 시작해 Enkino 전용 기능을 분류별로
재적용하는 방식이다.

1. upstream 구조와 2,933개 lib / 641개 Studio 테스트를 기준선으로 고정한다.
2. Cloudflare 정적 호스팅 파일과 Enkino 문서를 먼저 이식한다.
3. upstream `transport.js`를 유지하고 Enkino 호스트·대화상자 계약만 TDD로
   이식한다.
4. `rhwp-studio/src/main.ts`는 upstream 로드 흐름을 기준으로 임베드·로컬 글꼴·
   저장 안내 정책을 개별 포트한다.
5. lineseg 후검증 최소 패치를 upstream 조건에 맞게 재작성한다.
6. 자동 병합된 4개 파일을 수동 리뷰한다.
7. Rust·Studio·Enkino 호스트 회귀 테스트와 production build까지 통과한
   시점에서만 운영 동기화를 제안한다.
