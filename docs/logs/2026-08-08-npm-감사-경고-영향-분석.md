# npm 감사 경고 영향 분석

## 목적

`rhwp-studio` 의존성 설치 과정에서 보고된 npm 보안 감사 경고가 운영 RHWP 배포에 미치는 영향을 확인한다.

## 확인 결과

- 분석 일자: 2026-08-08
- 전체 감사: 취약점 5건
  - 낮음 1건
  - 보통 1건
  - 높음 3건
- 운영 의존성 감사: `npm audit --omit=dev` 기준 0건
- 분석 시점의 소스 및 잠금 파일 변경: 없음

전날 설치 시 표시된 4건과 개수가 다른 것은 npm 보안 감사 데이터가 갱신된 결과다. 현재 재조회 결과를 기준으로 기록한다.

## 의존 경로

확인된 패키지는 모두 빌드 도구의 간접 개발 의존성이다.

| 취약 패키지 | 유입 경로 | 주요 위험 |
| --- | --- | --- |
| `@babel/core@7.29.0` | `vite-plugin-pwa` → `workbox-build` | 빌드 입력의 `sourceMappingURL`을 통한 임의 파일 읽기 |
| `brace-expansion@2.1.0`, `5.0.6` | `vite-plugin-pwa` → `workbox-build` → `filelist`/`glob` | 공격자가 제어하는 패턴 처리 시 서비스 거부 |
| `fast-uri@3.1.2` | `vite-plugin-pwa` → `workbox-build` → `ajv` | 비정상 URI의 호스트 판별 혼동 |
| `nanoid@3.3.16` | `vite` → `postcss` | 크기 0인 사용자 정의 생성기 호출 시 무한 반복 |
| `postcss@8.5.20` | `vite` | 빌드 입력의 `sourceMappingURL`을 통한 파일 읽기 |

## 운영 영향 판단

현재 취약 패키지는 `devDependencies` 아래에만 존재한다. `npm audit --omit=dev` 결과도 취약점 0건이므로 Cloudflare Worker가 제공하는 정적 산출물의 런타임 의존성 취약점으로 분류하지 않는다.

주요 노출 지점은 신뢰할 수 없는 소스, 스타일시트, URI 또는 glob 패턴을 빌드 파이프라인 입력으로 처리하는 경우다. 현재 RHWP의 통상적인 저장소 소스 빌드에서는 외부 사용자가 빌드 입력을 직접 제공하지 않으므로 운영 위험은 낮다. 다만 개발자 또는 CI가 신뢰할 수 없는 브랜치를 빌드하는 공급망 상황에서는 영향 가능성이 남는다.

## 수정 가능 범위

`npm audit fix --dry-run` 결과 직접 의존성의 메이저 버전 변경 없이 잠금 파일의 간접 패키지를 갱신해 해소할 수 있다. 주요 변경 후보는 다음과 같다.

- `@babel/core`: `7.29.0` → `7.29.7`
- `brace-expansion`: `2.1.0` → `2.1.4`, `5.0.6` → `5.0.9`
- `fast-uri`: `3.1.2` → `3.1.5`
- `nanoid`: `3.3.16` → `3.3.18`
- `postcss`: `8.5.20` → `8.5.26`

dry-run은 총 21개 간접 패키지의 잠금 버전 변경을 예고했다.

## 조치 및 검증

운영 코드와 직접 의존성은 유지하고 `npm audit fix`로 `rhwp-studio/package-lock.json`의 간접 의존성만 갱신했다.

- `npm audit`: 취약점 0건
- `npm audit --omit=dev`: 취약점 0건
- `npm test`: 646개 통과, 실패 0개, 스킵 0개
- `npm run build`: production build 성공
- 변경 파일: `rhwp-studio/package-lock.json`과 이 작업 로그

이번 변경은 정적 산출물의 기능을 바꾸는 소스 변경이 아니므로 운영 재배포는 수행하지 않았다.
