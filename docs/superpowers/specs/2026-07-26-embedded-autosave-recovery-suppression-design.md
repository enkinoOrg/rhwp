# 임베드 환경 초기 자동복구 억제 설계

## 목적

Lawgent SDK가 RHWP Studio를 iframe으로 열고 서버의 HWPX 초안을 로드할 때, 브라우저에 남아 있는 다른 문서의 자동저장 복구 창이 먼저 표시되지 않게 한다. RHWP Studio를 단독으로 실행하는 사용자의 자동복구 기능은 유지한다.

## 현재 원인

Studio 초기화는 URL 문서 로드와 초기 자동복구 제안을 비동기로 함께 시작한다. Lawgent SDK의 `ready` 및 `loadFile` 메시지는 그 이후 도착하므로, `loadFile`의 `suppressDialogs` 옵션으로는 먼저 시작된 자동복구 창을 막을 수 없다.

## 선택한 동작

초기 자동복구 여부를 판단하는 기존 함수에서 다음 조건 중 하나가 참이면 복구 제안을 생략한다.

1. URL의 `url` 파라미터로 문서를 직접 여는 경우
2. Studio가 iframe 안에서 실행되는 경우 (`window.parent !== window`)

따라서 동작은 다음과 같다.

- Lawgent SDK를 포함한 iframe 임베드: 초기 자동복구 창을 표시하지 않는다.
- RHWP Studio 단독 실행: 기존처럼 자동저장 복구 후보를 표시한다.
- `?url=...` 직접 문서 로드: 기존처럼 초기 자동복구 창을 표시하지 않는다.

iframe 안에서 Studio를 사용하는 다른 소비자도 외부에서 문서를 공급하는 임베드 클라이언트로 간주한다. 특정 Lawgent 도메인이나 부모 origin에 결합하지 않는다.

## 변경 범위

- RHWP Studio의 초기 자동복구 생략 조건
- 해당 조건을 검증하는 단위 회귀 테스트

Lawgent SDK, 자동저장 데이터 구조, 복구 대화상자 UI, 기존 `suppressDialogs` 의미는 변경하지 않는다.

## 테스트 기준

회귀 테스트는 초기 자동복구 판단 함수의 실제 소스를 실행하여 다음을 검증한다.

1. 최상위 창이며 `url` 파라미터가 없으면 복구를 생략하지 않는다.
2. 최상위 창이며 `url` 파라미터가 있으면 복구를 생략한다.
3. iframe 안이며 `url` 파라미터가 없으면 복구를 생략한다.

구현 후 관련 단위 테스트와 Studio 빌드를 실행한다. 배포 후에는 Lawgent v2 프로젝트에서 이전 자동저장 복구본이 남아 있는 브라우저로 초안을 열어, 복구 창 없이 서버 초안이 로드되는지 확인한다.

## 실패 처리

iframe 접근은 동일 출처의 부모 DOM을 읽지 않고 `window.parent` 객체 동일성만 비교하므로 교차 출처 제약을 일으키지 않는다. 기존 자동저장 조회 및 복구 오류 처리는 변경하지 않는다.
