# RHWP 임베드 대화상자 억제 적용 지침 설계

## 목적

공용 RHWP Studio를 iframe으로 사용하는 Enkino 프로젝트가 `loadFile` 중 검증 대화상자 때문에 응답을 기다리며 멈추는 문제를 일관되게 해결할 수 있도록 적용 지침을 제공한다. 상세 지침은 RHWP 저장소를 단일 원본으로 관리하고, Lawgent 저장소에는 Lawgent 적용 현황과 원본 링크만 둔다.

## 산출물

### 공용 원본

- 위치: `docs/tech/2026-08-04-임베드-대화상자-억제-적용-지침.md`
- 소유 저장소: `enkinoOrg/rhwp`
- 역할: 다른 프로젝트가 복사해 적용할 수 있는 완전한 기술 지침

### Lawgent 안내

- 위치: `docs/guides/2026-08-04-rhwp-임베드-대화상자-억제-적용-안내.md`
- 소유 저장소: Lawgent
- 역할: Lawgent의 실제 적용 파일, 현재 소비 프로젝트 현황, 공용 원본 링크 제공
- 원칙: 공용 코드 예제와 운영 절차를 중복하지 않는다.

## 공용 원본 구성

1. 문제와 적용 조건
   - 임베드 HWPX 로드 중 비표준 `lineseg` 검증 모달이 RPC 응답을 막는 상황을 설명한다.
   - 대화형 검증이 필요한 일반 파일 열기에는 적용하지 않음을 명시한다.
2. 프로토콜 계약
   - `loadFile`의 `params.suppressDialogs`가 정확한 boolean `true`일 때만 모달을 생략한다.
   - 누락, `false`, 문자열 `"true"`는 기존 대화형 동작을 유지한다.
   - 생략 시 문서는 자동 보정하지 않고 `as-is`로 연다.
3. 적용 방식
   - vendored SDK의 `loadFile(data, fileName, options)` 확장 예제를 기본 방식으로 제시한다.
   - 직접 `postMessage`를 사용하는 최소 예제를 함께 제공한다.
   - 현재 공개 `@rhwp/editor` 어댑터에는 옵션 전달 경로가 없으므로 패치된 로컬 vendor 어댑터 또는 직접 `postMessage` 어댑터가 필요하다고 명시한다.
4. 보안과 호환성
   - 전송할 요청 필드를 `data`, `fileName`, `suppressDialogs`로 명시적으로 구성한다.
   - 호출자 options를 요청 객체에 그대로 펼치지 않는다.
   - 고정 target origin 및 응답의 origin/source 검증을 유지한다.
   - 옵션을 보내지 않는 기존 소비자는 동작이 바뀌지 않음을 설명한다.
5. 배포 순서
   - Studio의 프로토콜 지원 여부 확인 후 소비자 코드를 배포한다.
   - 소비자를 먼저 배포하면 구형 Studio가 옵션을 무시할 수 있으므로 기능 보장을 하지 않는다.
6. 검증
   - boolean `true` 요청은 모달 없이 완료되는지 확인한다.
   - 누락 및 비 boolean 값은 기존 모달 경로를 유지하는지 확인한다.
   - 운영 환경에서 로드 완료, iframe 유지, 읽기 전용 폴백 미발생을 확인한다.
7. 문제 해결과 롤백
   - 서비스워커 캐시, RPC timeout, 구형 Studio 번들, 옵션 누락을 진단 항목으로 둔다.
   - 소비자에서 옵션 전달을 제거하면 기존 동작으로 돌아가는 최소 롤백 절차를 제공한다.

## Lawgent 안내 구성

- 공용 원본의 GitHub 링크와 로컬 개발 경로를 제공한다.
- Lawgent의 vendored SDK, 타입 선언, 초안 편집기, 관련 테스트 파일을 열거한다.
- `2026/rhwp`, `2026/md-to-hwpx`, `2026/gyeonggi-arts`의 적용 상태를 표로 정리한다.
- `gyeonggi-arts`는 같은 Worker를 사용하지만 옵션을 보내지 않아 해당 기능이 활성화되지 않는다고 구분한다.
- 공개 npm SDK 전체에 전파된 변경이 아니라는 주의사항을 둔다.

## 비범위

- RHWP Studio, Lawgent 또는 `md-to-hwpx` 코드를 추가 수정하지 않는다.
- npm 패키지 버전 변경이나 배포를 수행하지 않는다.
- 검증 모달 외의 자동복구 및 저장 안내 대화상자 정책은 다루지 않는다.
- 문서 저장 API, 인증, Supabase 연동은 기존 외부 연동 가이드를 참조하고 반복하지 않는다.

## 검증 기준

- 두 문서의 파일명이 프로젝트 날짜 규칙을 따른다.
- 공용 원본만으로 세 적용 방식과 배포·검증·롤백 절차를 수행할 수 있다.
- Lawgent 안내는 공용 내용을 복제하지 않고 원본으로 연결한다.
- 코드 예제는 현재 구현의 엄격한 boolean 판정 및 명시적 요청 필드 구성을 반영한다.
- 문서에 `TODO`, `TBD`, 임시 링크 또는 확인되지 않은 패키지 지원 주장이 없다.
