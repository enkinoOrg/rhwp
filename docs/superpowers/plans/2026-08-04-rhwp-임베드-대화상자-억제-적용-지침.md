**Goal:** Publish one canonical RHWP integration guide for `suppressDialogs` and one Lawgent-specific pointer document without duplicating the shared procedure.

**Architecture:** The `enkinoOrg/rhwp` repository owns the complete protocol, security, rollout, verification, troubleshooting, and rollback guidance. The Lawgent repository owns only its local adoption map and links to the canonical guide, so future protocol changes have one documentation source of truth.

**Tech Stack:** Markdown, RHWP iframe `postMessage` protocol, vendored JavaScript/TypeScript SDK, Git

- `params.suppressDialogs`가 정확한 boolean `true`일 때만 검증 모달을 생략한다고 명시한다.

- 문서는 자동 보정하지 않고 `as-is`로 연다고 명시한다.

- `md-to-hwpx`의 `.github/workflows/deploy.yml`을 변경하거나 실행하지 않는다.
- 사용자의 기존 수정 파일과 미추적 파일은 커밋하지 않는다.

- [ ] **Step 1: 적용 경계와 계약 작성**

  배경, 적용 대상, 비적용 대상을 먼저 설명한다. `suppressDialogs === true`만 활성화되며 이때 검증 경고를 `as-is`로 열고 자동 보정하지 않는다는 계약을 적는다. 일반 파일 열기와 옵션 누락 요청은 기존 모달을 유지한다고 구분한다.

- [ ] **Step 2: vendored SDK 최소 패치 예제 작성**

  다음 형태를 포함하고 호출자 options를 요청 객체에 펼치지 않는 이유를 설명한다.

  ```ts
  export type LoadFileOptions = {
    suppressDialogs?: boolean
  }

  async function loadFile(
    data: ArrayBuffer | Uint8Array,
    fileName = 'document.hwp',
    options: LoadFileOptions = {},
  ) {
    const buffer = copyToTransferableBuffer(data)
    return request('loadFile', {
      data: buffer,
      fileName,
      suppressDialogs: options.suppressDialogs === true,
    }, [buffer])
  }
  ```

  소비자 호출은 다음과 같이 고정한다.

  ```ts
  await editor.loadFile(bytes, fileName, { suppressDialogs: true })
  ```

- [ ] **Step 3: 직접 postMessage 적용 예제 작성**

  고정 origin, 요청 ID, transferable buffer를 사용하는 다음 최소 계약을 포함한다.

  ```ts
  const buffer = bytes.slice().buffer
  frame.contentWindow?.postMessage({
    type: 'rhwp-request',
    id: requestId,
    method: 'loadFile',
    params: {
      data: buffer,
      fileName,
      suppressDialogs: true,
    },
  }, RHWP_STUDIO_ORIGIN, [buffer])
  ```

  응답은 `event.origin === RHWP_STUDIO_ORIGIN`과 `event.source === frame.contentWindow`를 모두 만족할 때만 처리한다고 명시한다.

- [ ] **Step 4: 공개 SDK 제한과 배포 순서 작성**

  `@rhwp/editor` 공개 어댑터에는 현재 세 번째 options 인자가 없으므로 패치된 vendor 어댑터 또는 직접 postMessage 어댑터가 필요하다고 적는다. Studio 프로토콜 지원을 먼저 배포·확인한 뒤 소비자를 배포하는 순서를 제시한다.

- [ ] **Step 5: 테스트·운영 검증·롤백 작성**

  다음 검증을 체크리스트로 포함한다.

  - boolean `true`: 모달 호출 없이 `loadFile` 응답 완료
  - 옵션 누락 및 문자열 `"true"`: 기존 모달 경로 유지
  - 운영: HWPX 로드 완료, iframe 유지, 읽기 전용 폴백 미발생
  - 문제 해결: 서비스워커 캐시, 구형 Studio 번들, RPC timeout, 소비자 옵션 누락
  - 롤백: 소비자에서 세 번째 인자 제거 후 기존 대화형 동작 확인
